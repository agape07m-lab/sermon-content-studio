# 원고 동기화 운영 기준

공개 읽기 목록은 `agape07m-lab/sermon-content-studio` 저장소의 `main`, `noan-sermon-study/latest.json`이다. 앱 주소는 https://black-feather-52eb.noan-central-3354fde.workers.dev/ 이다. 원고 작성 일정과 집필 지침은 이 문서의 변경 대상이 아니다.

## 게시 전 확인

완료된 응답 안에서 서론부터 결론까지 이어지는 설교·강의 원고 전체를 읽는다. `content_truncated`, 실패, 사용자 조치 필요, 중간 작성, 일부 대지만 수정한 답변, 이전 자료 안내, 요약, 파일 링크만 있는 결과는 게시하지 않는다. 글자 수는 보조 검사이며 완료 판정을 대신하지 않는다. 부분 수정 요청 뒤 전체 완료본이 없으면 이전 공개본을 유지한다. 원문 전체를 확인할 수 없는 첨부파일도 보류한다.

실명과 결합된 심방·상담·가정·건강·금전 사정, 연락처, 주소, 식별정보, 비밀번호와 키를 원고 전체에서 확인한다. 성경 속 인물과 일반적인 생활 예시는 사적인 심방 사례와 구별한다. 의심이 남으면 원문을 공개하거나 임의로 익명화해 게시하지 않고 보류한다. 패턴 검사는 보조 수단이며 문맥 검토가 필수다. 보류 이유와 민감한 원문은 공개 저장소에 쓰지 않는다.

## 호환 형식과 보관

`schema: 1`, `updatedAt`, `items[]`와 기존 부가 필드를 유지한다. 수요기도회 `kind: wednesday`, 주일예배 `kind: sunday`, 성경개관 `kind: overview`는 각각 서로 다른 최근 원고 두 편을 보관한다. 새벽예배 `kind: dawn`는 기존 한 편을 유지한다.

`manuscriptId`는 일반 설교의 경우 `kind-YYYY-MM-DD`, 성경개관은 `overview-episode-N`이다. 최신 항목의 `id`는 기존 독자를 위해 `wednesday`, `sunday`, `overview`, `dawn` 중 해당 값을 사용하고 직전 항목의 `id`는 `manuscriptId`를 사용한다. 각 항목의 `kind`로 분야를 판별한다. 같은 원고의 새 전체 수정본은 같은 `manuscriptId`를 갱신하며 두 자리를 차지하지 않는다. 일반 설교는 실제 예배일 내림차순, 성경개관은 회차 내림차순으로 정렬하고 같은 원고의 수정본은 실제 완료 시각으로 비교한다. 오래된 원고를 오늘 수정해도 최근 예배의 자리를 밀어내지 않는다. 48시간 제한은 없다.

항목은 `id`, `manuscriptId`, `title`, `date`, `passage`, `kind`, `status: full`, `origin`, `sourceTimestamp`, `sourceThreadId`, `sourceMessageId`, `content`, `review`를 포함한다. `sourceTimestamp`는 원문 응답·실행의 실제 완료 시각이며 점검 시각으로 대신하지 않는다. 성경개관은 `sequence` 정수도 기록한다. 예배일을 확인하지 못했지만 회차가 확실한 성경개관은 `date: ""`와 `dateNote`를 사용한다. 날짜를 추정하거나 예시 날짜를 넣지 않는다. 주일 2026-11-08 「은혜가 가르치는 삶」은 사용자가 날짜를 확인했다.

`review`는 전체 원고의 완료 확인과 개인정보 확인을 마친 경우에만 `completion: passed`, `privacy: passed`, `contentSha256: <content UTF-8 원문의 SHA-256 64자리 소문자>`를 기록한다. 이것은 설교자의 최종 승인이나 신학적 무오류 보증을 뜻하지 않는다. 원문을 수정하면 다시 검토하고 해시를 다시 계산한다. 원고 전문을 요약·재집필하지 않는다. 대화의 부연 설명과 쓰기 블록 껍데기, 표시되지 않는 내부 인용 마커만 제외할 수 있다. 원고에 속한 기도문·강의자 참고는 보존한다.

## 쓰기와 재검증

1. 최신 브랜치 파일과 blob SHA를 `fetch_file`로 읽는다. 쓰기 전에 원본 JSON, SHA, 시각을 해당 실행의 비공개 작업 폴더에 백업한다. 공개 저장소의 이전 커밋도 복구 지점이다.
2. 검토한 후보만 준비한다. `scripts/prepare-feed.cjs`와 `public/feed.js`의 병합·검증 규칙을 사용한다. 로컬에서는 `node scripts/prepare-feed.cjs base.json reviewed-candidates.json next.json`으로 만들고 `node --test --test-isolation=none tests/feed.test.cjs`를 실행한다. 기존 다른 분야 항목과 부가 필드를 보존하고 분야별 두 편을 유지한다. 기존 파일에 새벽예배 legacy 항목만 review가 없는 경우는 호환을 위해 허용한다. 새 후보는 review가 필수다.
3. 내용과 메타데이터 변화가 없으면 `updatedAt`도 바꾸지 않고 종료한다. 같은 원고의 동일 완료 시각에 서로 다른 본문이 있으면 보류한다.
4. 방금 읽은 SHA를 지정해 `update_file`로 `latest.json`만 교체한다. 충돌하면 최신 파일을 다시 읽고 다시 병합·검증한 뒤 한 번만 재시도한다. 이전 전체 파일을 강제로 덮어쓰지 않는다.
5. 저장 후 `fetch_file`로 다시 읽어 JSON, 분야별 편수, 제목·날짜·회차·원문 해시를 확인한다. 가능하면 앱에서 최근·직전 원고가 열리는지 확인한다. 실제 확인 없이 성공이나 모바일 실기 검증을 주장하지 않는다.

2026-11-24 사용자 지시에 따라 매시간 Codex 점검을 중단했다. 사용량을 아끼기 위해 이 반복 점검을 다시 만들지 않는다. 원고 작성 작업을 마친 뒤 그 작업에서 한 번 전달하거나, 사용자가 완성 원고의 동기화를 요청했을 때 한 번 실행한다. 일반 채팅의 완료를 자동으로 통지받는 연결은 없으므로 모든 채팅을 주기적으로 조회하여 완료를 찾지 않는다.

동기화 실행 시 지정된 원고의 출처를 `read_thread(threadId, turnLimit:10, maxOutputCharsPerItem:20000)`와 필요한 커서로 읽는다. 최대 글자 수에 걸리거나 파일 본문이 빠지면 완료로 판정하지 않는다. 새 주일·수요·성경개관 채팅도 실제 본문에서 예배 종류·제목·예배일·완결성을 확인한다. 요약·미리보기를 게시 원고로 사용하지 않는다. 완료된 대상 원고의 검증·병합에 필요한 범위만 확인하고 다른 채팅에 메시지를 보내거나 새로운 원고를 작성하지 않는다.

기존 ChatGPT 예약 원고는 새벽예배 `6ac57c410aa48191a31157d7c22cc670`, 수요기도회 `6aea53e9ae9081919670772483521564`, 성경개관 `Automation_cbc7ae54c6408191827a804f02d29290`에서 작성이 완료된 뒤 같은 규칙으로 전달한다. 작성 지침·일정은 유지한다. 결과의 전문을 얻을 수 없으면 게시하지 않는다. 별도의 정기 누락 점검으로 이 대화에서 반복 동기화를 재개하지 않는다.

앱은 시작·다시 활성화·연결 복구 시와 열어 둔 동안 5분마다 이미 게시된 JSON 목록을 읽는다. 이 목록 읽기는 GPT를 호출하지 않는다. 원고 전달이 끝난 뒤 휴대폰에서 앱을 다시 열거나 다시 활성화하면 게시된 원고를 받아 볼 수 있다. 서버에서 ChatGPT 대화를 직접 감시하는 실시간 웹훅은 없다. 동기화 실행에는 실행 환경과 계정 연결이 필요하며 지연될 수 있다. 변경이 없으면 알리지 않고, 게시 완료·실패·사용자 조치 필요 시에만 알린다.
